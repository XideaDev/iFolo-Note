## 0. 一句话结论

把当前"列表 ↔ 编辑器二选一"的**展开态**，升级为**面板宽度 ≥ 500px 时自动生效的左右分屏笔记**：左侧保持笔记卡片流与检索，右侧常驻当前笔记编辑器。用户浏览、检索、切换笔记时不再丢失编辑上下文，同时保留 < 500px 的紧凑单栏形态作为默认轻量入口。

## 1. 背景与现状

### 1.1 当前形态

iFolo 是一个从屏幕右边缘滑出的悬浮笔记面板，当前宽度可拖拽调整：

- 原生侧：`PanelController.maxAllowedWidth` = `max(720, 屏幕可见宽度 / 2)`；默认宽度 450px（`currentWidth` 回退值）。
- Web 侧：`PanelResizer` 允许 320px ~ 屏幕一半，拖动左边缘调节。
- 视图：`viewMode: 'list' | 'editor' | 'settings' | 'trash' | 'dev'`，**互斥**切换（`main.ts:837`）。
- 打开笔记：`selectNoteFromList()` → `openNote()` → `switchViewMode('editor')`，列表 DOM 被 `display:none`，编辑器占满整个面板。

### 1.2 核心问题

| 问题 | 表现 | 影响 |
| :--- | :--- | :--- |
| 上下文断裂 | 打开笔记后列表消失，回列表必须 `Esc` / `⌘L` / 返回 | 连续整理、批量改写、边查边写时反复跳转 |
| 大屏浪费 | 面板拖到 600–900px 后，编辑器仍单列铺满，行长过长（> 90 字符） | 阅读回扫成本高，排版不专业 |
| 检索与编辑割裂 | 搜索只能回到列表，结果与正文无法同屏比对 | 语义检索的价值被削弱 |
| 切换成本 | 每次切换笔记都是一次整页替换 | 心流被打断，与"随手记录"的产品哲学相悖 |

### 1.3 为什么是 500px

- 450px 是当前默认宽度，必须保持"轻量单栏"体验不变。
- 500px 是"能放下 200px 列表 + 1px 分隔 + ≥ 296px 编辑区"的最小可行宽度。
- 500px 以下强行分屏会导致标题与正文严重截断，违背项目"防截断"视觉铁律。

> **术语统一**：本文中的"展开态"= 面板宽度 ≥ 500px 的大屏态；"紧凑态"= 面板宽度 < 500px。

**现状的结构性约束**

1. `viewMode` 是排他的 4 状态，`switchViewMode()` 内部直接操作各 DOM 的 `display`（`main.ts:837-923`）。分屏需要把"路由"与"布局"拆开，否则会出现 `list` 与 `editor` 同时可见的非法状态。
2. `buildShell()` 只允许一次挂载（AGENTS.md 铁律）。分屏不能重建 `NoteList`，只能把现有节点移入新的 grid 容器。
3. `PanelController.maxAllowedWidth` 目前是屏宽一半，860px 展开宽度在 1440 屏上会被截到 720px，必须同步调整原生上限。
4. `PanelResizer` 与原生 `setWidth` 双向写宽度；分屏的 500px 判定必须同时监听这两条路径，不能只监听 CSS。

## 2. 目标与非目标

### 2.1 产品目标

1. **同屏不丢上下文**：在展开态下，列表与编辑器同时可见，单击即预览，双击/回车进入编辑。
2. **宽度自适应**：500px 自动进入分屏，无需用户手动开启；拖拽跨过阈值时平滑切换。
3. **保留轻量入口**：< 500px 时仍是原来的单栏体验，不增加任何认知负担。
4. **视觉零违和**：完全复用现有 Design Token，不引入新色、新阴影体系、新字体。
5. **行为可预期**：切换、删除、搜索、锁屏、缩放等边界都有确定规则，不出现空白面板或内容错位。

### 2.2 非目标（本期不做）

- 不做三栏（列表 + 编辑器 + 大纲/预览）。
- 不做同一面板内左右两个**编辑器**（仅一个编辑区）。
- 不做多窗口拆分（macOS 原生多窗口另立项）。
- 不做拖拽卡片到编辑区生成双链/引用。
- 不改动 ProseMirror Schema、Markdown 序列化协议。
- 不改动 MCP、加密、回收站的数据结构。

## 4. 核心概念与状态模型

### 4.1 两个正交维度

将现有单一的 `viewMode` 拆成 **路由（Route）** 与 **布局（Layout）** 两个维度，避免状态爆炸：

```
Route   : list | editor | settings | trash | dev
Layout  : compact | split | focus
```

- **Route** 决定"当前在哪个功能页面"。
- **Layout** 只决定"列表与编辑器如何排布"，仅在 `route = list | editor` 时生效。
- `settings / trash / dev` 始终独占整个面板，忽略 Layout。

### 4.2 布局状态

| 状态 | 触发条件 | 视觉 | 说明 |
| :--- | :--- | :--- | :--- |
| `compact` | 面板宽度 < 500px | 单栏：列表 **或** 编辑器 | 保持现状；由 `route` 决定显示谁 |
| `split` | 面板宽度 ≥ 500px 且未开启专注 | 左列表 + 1px 分隔 + 右编辑器 | 本期核心 |
| `focus` | 宽度 ≥ 500px 且用户主动专注 | 单栏编辑器 + 悬浮"显示列表"按钮 | 可选能力，`⌘\` 二次切换 / `Esc` 退出 |

### 4.3 布局判定函数

```ts
function resolveLayout(width: number, pref: 'auto' | 'focus'): Layout {
  if (width < 500) return 'compact'
  if (pref === 'focus') return 'focus'
  return 'split'
}
```

**阈值滞回（仅拖拽期间）**：进入分屏用 500px，退出用 488px，避免用户在 499/500 边界拖动时布局抖动。松手后以 500px 为准。

### 4.4 状态迁移图

```
                 width < 500                 width >= 500
   ┌────────┐  ───────────────▶  ┌────────┐  ─────────────▶  ┌───────┐
   │compact │                    │compact │                   │ split │
   │(list)  │  ◀───────────────  │(editor)│  ◀─────────────   │       │
   └────────┘   width < 500      └────────┘   width < 500     └───────┘
        │ 点击卡片                    ▲                            │ ⌘\ / 专注按钮
        └────────────────────────────┘                            ▼
                                                              ┌───────┐
                                                              │ focus │
                                                              └───────┘
```

迁移规则：

1. `compact + route=list` 点击卡片 → `compact + route=editor`（单栏进入编辑，保留返回按钮）。
2. `compact + route=editor` 面板拉宽 ≥ 500 → `split`，列表自动出现在左侧，当前笔记保持在右侧，**不重建编辑器实例**。
3. `split` 面板缩窄 < 500 → `compact + route=editor`，保留当前笔记；不退回列表（避免用户丢失正在写的内容）。
4. `compact + route=list` 拉宽 ≥ 500 → `split`，右侧显示上次活动笔记；若无活动笔记则显示编辑器空态。
5. `split` 点击"专注"或 `⌘\` → `focus`；再次触发 → `split`。
6. 进入 `settings / trash / dev` 前记录 `layoutPref` 与 `activeId`，返回时恢复。

## 6. 交互流程

### 6.1 进入分屏

**路径 A：拖拽面板左边缘**

1. 用户按住面板左边缘 `panel-resizer`（6px 热区，`ew-resize`）。
2. 宽度实时增长；到 500px 时：
   - 列表从左侧淡入（`opacity 0→1` + `translateX(-8px)→0`，160ms）；
   - 编辑器从满宽平滑收窄到右列（宽度由 grid 过渡，220ms）；
   - 分隔线出现（1px，`--border-subtle`）；
   - 顶栏右侧出现"收起分屏"图标（`⌘\` tooltip）。
3. 松手后持久化 `ifolo.panelWidth`；若 ≥ 500，同时写入 `ifolo.splitSeen = true`（用于首次引导）。

**路径 B：点击顶栏"展开分屏"按钮**

1. 当前宽度 450px，点击按钮。
2. 面板宽度以 `320ms cubic-bezier(.32,.72,0,1)` 动画到 `lastExpandedWidth`（默认 860px，上限为原生允许最大值）。
3. 动画期间禁用分隔线拖拽；动画结束后列表获得一次 `focus()` 但不抢占输入光标（`preventScroll`）。
4. 若当前没有活动笔记：右侧显示编辑器空态（"选择左侧笔记开始编辑"）。

**路径 C：`⌘\`**

- `compact` → 执行路径 B。
- `split` → 收起到 450px，回到 `compact + route=editor`。
- `focus` → 回到 `split`。

**路径 D：双击列表卡片**

- 在 `compact` 下：进入编辑器并聚焦正文。
- 在 `split` 下：仅将预览标签转正 + 聚焦正文，不改变布局。

### 6.2 退出分屏

| 方式 | 行为 |
| :--- | :--- |
| 点击"收起分屏" | 宽度动画到 450px，进入 `compact + editor`，保留当前笔记 |
| 拖拽左边缘 < 500px | 同上，但动画关闭（跟手） |
| `⌘\` | 同上 |
| `Esc`（编辑器内） | 先关弹层/清搜索，再退出专注，最后不主动收起分屏（避免误触） |
| 点击顶栏返回 | `split` 下返回按钮隐藏；`compact + editor` 下返回列表 |

> **设计取舍**：收起分屏不回到列表，而是留在编辑器。理由：用户刚在写内容，收起只是"让面板变窄"，不是"离开笔记"。

### 6.3 浏览与切换笔记

1. 单击卡片：
   - 若存在未保存修改，先 `flushSave()`（最多等待 120ms）。
   - 加载目标笔记，`activeId` 更新。
   - 列表活动行高亮（`--card-bg-active` + `--blue-200` 边框）。
   - 右侧编辑器替换文档，滚动到顶部；**不自动聚焦**（焦点留在列表，方便方向键连续浏览）。
   - 标签：若该笔记未在 `openTabIds` 中，设为 `previewTabId`（斜体预览态），替换上一个预览标签。
2. 双击卡片 / `Enter`：
   - 同上，但聚焦正文，光标置于文首；预览标签转正。
3. `↑ / ↓`：
   - 在当前筛选结果内移动活动行，实时预览（同单击），带 80ms 节流。
   - 到顶/到底不循环，避免误操作。
4. `Tab`：
   - 焦点从列表移到编辑器正文；`Shift+Tab` 回到列表。
5. 编辑正文：
   - `tr.docChanged` 后 200ms 防抖：预览标签转永久、列表标题/摘要实时更新、保存状态变"保存中…"。
   - 保存成功后 600ms 回到"已保存"。

### 6.4 新建笔记

1. 点击 `+` / `⌘N`。
2. 在当前筛选上下文创建：
   - 若当前筛选是具体分类（如"技术架构"），新笔记归入该分类；
   - 若当前是"全部 / Todos / 搜索态"，归入未分类。
3. 新笔记插入列表顶部（置顶区之下），立即成为活动行并滚动入视。
4. 右侧编辑器清空，聚焦标题（首行 H1）。
5. 标签以**永久态**打开（新建即有意向，不应被下一次预览替换）。
6. 空列表时同样适用；创建后空态消失。

### 6.5 删除笔记

1. 点击卡片悬浮的删除按钮。
2. 卡片执行 220ms 退场：`opacity→0`、`translateX(28px) scale(.95)`、`max-height→0`。
3. 动画结束后移入回收站（数据层），列表重排。
4. 若删除的是活动笔记：
   - 选择当前可见顺序中的**下一条**；没有则选**上一条**；
   - 若列表为空：进入双栏空态（不自动新建空白笔记）；
   - 标签同步关闭；若关闭的是最后一个标签，右侧显示空态。
5. Toast："已移入回收站" + "撤销"（5s 内可恢复）。

### 6.6 搜索与筛选

- 搜索框固定在列表顶部（保持现有"搜索框常驻"铁律）。
- 输入时列表实时过滤；右侧编辑器**保持当前笔记不变**。
- 若当前笔记不在结果中（搜索或分类筛选均适用）：
  - 列表顶部出现一条 10.5px 提示："当前笔记不在筛选结果中"；
  - 右侧顶部出现同款细提示条，可点击"回到全部"。
- `Esc`：
  - 有搜索词 → 清空搜索；
  - 无搜索词 → 输入框失焦；
  - 永不因此收起搜索框或退出分屏。
- 切换分类 chip：
  - 列表范围变化，TabStrip 按当前活动笔记分类重新渲染（不因筛选而清空标签）。

### 6.7 加密笔记（保险箱）

1. 列表行显示锁图标，摘要显示"受保护的私密笔记（验证身份后查看）"。
2. 单击后在右侧显示锁定遮罩（沿用 `lockOverlayEl`）：
   - 锁图标 + 标题 + "轻触 Touch ID 或输入密码解锁"；
   - 列表其余笔记仍可浏览，但右侧保持锁定态直到解锁或切换。
3. 解锁成功：正文淡入（180ms），列表摘要解除遮蔽。
4. 会话锁定（`⌥⌘L`）：右侧立即回到锁定遮罩，列表重新遮蔽；分屏布局不变。
5. 锁定笔记在分屏下**不得**在列表摘要、搜索结果、Toast 中泄露正文片段。

### 6.8 分隔线拖拽

1. 分隔线视觉 1px，命中区 6px（左右各 2.5px），`cursor: col-resize`。
2. 拖拽范围：列表 `196px ~ min(320px, 面板宽度 - 296px - 1px)`。
3. 拖拽时：
   - 禁用面板宽度过渡与列表卡片 hover 位移；
   - 显示浮动列宽提示（如 "248px"），松手 600ms 后消失；
   - 编辑器内容不重排抖动（`min-width:0` + `overflow:hidden`）。
4. 双击分隔线：复位为 `clamp(32%, 196px, 300px)`。
5. 持久化 `ifolo.listWidth`；面板缩到 < 500 时保留值，下次展开复用。

## 7. 主视图与笔记区联动逻辑

### 7.1 单一事实源

```
activeId  ──┬──▶ NoteList.activeId         （高亮、滚动入视）
            ├──▶ Editor.load(activeId)      （文档内容）
            ├──▶ TabStrip.activeId          （活动标签）
            └──▶ Topbar.crumb               （分类 / 标题 / 保存态）
```

- 任何入口（列表点击、标签点击、新建、删除、回收站恢复、MCP 外部变更）都必须走 `openNote(id)`，禁止各自修改 DOM。
- `openNote` 内部顺序固定：`flushSave → load → updateState → update activeId → render list/tabs/crumb`。

### 7.2 事件联动表

| 事件 | 列表 | 编辑器 | 标签 | 顶栏 |
| :--- | :--- | :--- | :--- | :--- |
| 单击卡片 | 活动行切换 | 载入文档，滚顶，不聚焦 | 预览标签替换 | 面包屑更新 |
| 双击卡片 | 活动行切换 | 载入并聚焦 | 预览转永久 | 面包屑更新 |
| 正文输入 | 标题/摘要 200ms 后更新 | 保存态"保存中…" | 预览转永久 | 保存态更新 |
| 保存成功 | — | — | — | 600ms 后"已保存" |
| 标签点击 | 活动行滚动入视 | 载入文档 | 活动标签切换 | 面包屑更新 |
| 关闭标签 | 若关的是活动项，选中相邻 | 载入相邻或空态 | 移除标签 | 更新 |

### 7.3 保存与切换的竞态

- 采用"**先落盘、后切换**"：`flushSave()` 返回 Promise，超时 120ms 视为失败。
- 失败时：
  - 阻止切换，当前文档保持；
  - Toast："保存失败，已保留当前编辑" + "重试"；
  - 列表活动行不改变，避免"看起来切了但内容没保存"。
- 快速连续点击（> 5 次/秒）：使用 `pendingOpenId` 只保留最后一次意图，避免加载风暴。
- 外部 MCP 追加与本地脏状态冲突：显示顶部细条"检测到外部修改"，提供"重新加载 / 保留我的编辑"，不做静默覆盖。

### 7.4 焦点策略

| 场景 | 焦点 |
| :--- | :--- |
| 单击卡片（分屏） | 留在列表 |
| 双击 / Enter | 编辑器正文 |
| 新建 | 标题行 |
| 关闭标签后 | 编辑器正文（若有）否则列表 |
| 面板展开动画结束 | 不主动抢焦点；仅当原本焦点在面板内才恢复 |
| 从其他 App 呼出面板 | 保持原有 `takeKey()` 行为，聚焦搜索框或编辑器 |

> 关键：分屏浏览时**单击不抢焦点**，否则方向键无法连续预览，且会打断"边看边挑"的节奏。

### 7.5 滚动位置

- 列表：每个筛选条件维护独立 `scrollTop`（会话内）。
- 编辑器：`Map<noteId, scrollTop>`，切换回来时恢复；新建/删除清理对应项。
- 活动行变化时 `scrollIntoView({ block: 'nearest' })`，避免整列表跳动。

### 8.5 窄分屏降级规则（500–639px）

500px 是最小可行分屏，必须做信息降级，否则列表与工具栏都会截断：

| 区域 | 常规（≥ 640px） | 窄分屏（500–639px） |
| :--- | :--- | :--- |

| 卡片时间 | 显示相对时间 | 隐藏，悬浮操作区保留 |
| 卡片标签 | 最多 3 个 | 隐藏，摘要保持单行 |
| 置顶徽标 | 显示 | 隐藏（置顶排序仍然生效） |
| 工具栏 | 标题、B/I/U/S、代码、链接、高亮、表情、更多、锁 | 仅保留标题、B/I/U/S、代码、锁；其余收进"更多" |
| 正文 H1 | 20px | 18px |
| 正文左右内边距 | 22px | 16px |
| 搜索占位文案 | "搜索笔记标题、内容，或输入 / 触发命令…" | "搜索笔记，或输入 / 命令…" |

> 原则：**先砍装饰，再砍功能**。时间、标签、置顶徽标是装饰性信息；新建、搜索、锁、正文编辑不可砍。

### 8.6 原生窗口约束（必须同步修改）

现状 `maxAllowedWidth = max(720, 屏宽/2)`。分屏建议宽度 860px，在 1440px 屏幕上上限 720px，**不够**。需求：

```swift
// 建议：分屏能力上限提升到 62% 屏宽，并保证至少 900pt
func maxAllowedWidth(on screen: NSScreen? = nil) -> CGFloat {
    let scr = screen ?? targetScreen()
    let wide = floor(scr.visibleFrame.width * 0.62)
    return max(900, min(1200, wide))
}
```

- 默认宽度仍为 450px，不影响老用户。
- 屏幕宽度 < 1200px（如 1280 屏）时，62% = 793，`max(900, …)` 会超出半屏较多；需产品确认是否接受遮挡。**回退方案**：`max(760, 0.58 * 屏宽)`，分屏最小宽度 500 仍可用，只是默认展开宽度降为 760。
- 多显示器切换时重新计算并 clamp；不得让面板超出 `visibleFrame`。

- 尊重 `prefers-reduced-motion: reduce`：宽度动画降为 0ms，仅保留 80ms 透明度变化。

### 9.7 焦点可见性

- 键盘焦点环：`outline: 2px solid var(--blue-200); outline-offset: 1px;`，仅 `:focus-visible` 生效。
- 列表行 `tabindex="0"`，`aria-selected` 标记活动项。
- 分隔线支持键盘：聚焦后 `←/→` 调整 8px，`Home/End` 到最小/最大。

## 11. 技术实现方案

### 11.1 前端结构改造

**目标**：不破坏 `buildShell()` 单次挂载铁律，不重复 `new NoteList()`。

```
#app
├── .panel-resizer
├── .topbar
├── .workspace[data-layout]
│   ├── .workspace__list      ← noteList.dom 挂载点
│   ├── .workspace__splitter
│   └── .workspace__editor    ← tabstrip + toolbar + editorSearch + editorScroll
├── .settings-view / .dev-view / .trash-view（绝对定位覆盖 workspace）
└── .statusbar
```

改造要点：

1. `buildShell()` 中新增 `.workspace` 容器，把 `noteList.dom`、`tabstrip`、`toolbar.dom`、`editorSearch.dom`、`editorScrollEl` 移入；仍只 `replaceChildren` 一次。
2. 新增 `applyLayout(layout: Layout)`：
   - 设置 `workspace.dataset.layout`；
   - 控制列表/编辑器 `display`（compact 时二选一）；
   - 调用 `view.requestMeasure()`（ProseMirror 宽度变化必须重测）；
   - 更新顶栏按钮与 `aria` 状态。
3. `switchViewMode(mode)` 拆为 `setRoute(route)` + `applyLayout()`，路由切换只控制 `settings/trash/dev` 覆盖层，不再直接 `display:none` 列表/编辑器。
4. 新增 `SplitController`（约 200 行）：
   - 监听 `ResizeObserver` / `window.resize`；
   - 维护 `layoutPref`、`listWidth`；
   - 分隔线拖拽与键盘调节；
   - 持久化。
5. `PanelResizer` 增加 `onWidthChange` 回调（当前已有），把宽度写入 `SplitController`；展开/收起动画用 CSS `transition: width` 或原生 `setFrame(animate:)`。
6. `selectNoteFromList` 在 split 下不再 `switchViewMode('editor')`，只更新 `activeId` 与文档。

### 11.2 关键代码骨架

```ts
type Layout = 'compact' | 'split' | 'focus'

const SPLIT_MIN = 500
const SPLIT_EXIT = 488
const LIST_MIN = 196
const LIST_MAX = 320
const EDITOR_MIN = 296

function resolveLayout(width: number, pref: 'auto' | 'focus'): Layout {
  if (width < SPLIT_MIN) return 'compact'
  if (pref === 'focus') return 'focus'
  if (width - LIST_MIN - 1 < EDITOR_MIN) return 'compact'
  return 'split'
}

function applyLayout() {
  const layout = resolveLayout(panelWidth, layoutPref)
  workspace.dataset.layout = layout
  splitter.hidden = layout !== 'split'
  // compact 下由 route 决定显示列表还是编辑器
  const showList = layout === 'split' || (layout === 'compact' && route === 'list')
  const showEditor = layout !== 'compact' || route === 'editor'
  listPane.hidden = !showList
  editorPane.hidden = !showEditor
  if (layout === 'split') {
    workspace.style.setProperty('--list-w', `${clampListWidth()}px`)
  }
  view?.requestMeasure()
  updateTopbar()
}
```

## 12. 验收标准（Given / When / Then）

1. **自动分屏**：Given 面板 499px，When 拖到 500px，Then 500ms 内出现左列表 + 分隔线 + 右编辑器，且当前笔记内容不变。
2. **自动收起**：Given 分屏且正在编辑，When 拖到 480px，Then 变为单栏编辑器，正文与光标位置保留。
3. **一键切换**：Given 450px，When 按 `⌘\`，Then 320ms 动画展开到 860px 并分屏；再按一次回到 450px 单栏。
4. **列表联动**：Given 分屏，When 单击第 3 条笔记，Then 第 3 条高亮、右侧显示其内容、焦点仍在列表。
5. **预览标签**：Given 分屏，When 连续单击 3 条不同笔记，Then 只产生 1 个斜体预览标签，不堆满标签栏。
6. **编辑转正**：Given 预览标签，When 在正文输入 1 个字符，Then 标签变永久、列表标题/摘要 200ms 内更新。
7. **搜索不丢内容**：Given 正在编辑，When 搜索"架构"，Then 列表过滤，右侧内容不变，且出现"当前笔记不在结果中"提示（若不匹配）。
8. **分隔线**：Given 分屏，When 拖动分隔线，Then 列表 196–320px 之间变化，编辑器不小于 296px，松手后刷新仍保留。
9. **删除**：Given 活动笔记在列表中间，When 删除，Then 220ms 退场后自动选中下一条，右侧同步。
10. **空态**：Given 删除最后一条笔记，Then 左右均显示空态，不自动新建。
11. **锁定**：Given 加密笔记，When 在分屏中打开，Then 右侧显示锁定遮罩，列表摘要不泄露正文。
12. **视觉一致**：分屏所有颜色、字号、圆角、阴影均来自 `tokens.css`，无新增硬编码色值（`#5CA3FF` 不用于文字）。
13. **性能**：500 条笔记下，拖动分隔线帧率 ≥ 50fps；切换笔记 < 100ms。
14. **可访问性**：仅键盘可完成"展开分屏 → 选择笔记 → 编辑 → 收起"全流程。
